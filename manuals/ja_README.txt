AI Toolkit ポータブル版 - MiniMax-H3-Image LoRA - Node.js も npm も不要
対象：Windows 10/11、RTX 3090 24 GB、RAM 64 GB
=============================================================================

言語
  各 .bat ファイルは最初に言語を選びます（英語、フランス語、ドイツ語、
  スペイン語、ポルトガル語、日本語、中国語）。10 秒以内に応答がなければ
  前回選んだ言語のままです。インターフェースでは右上のセレクターで
  いつでも言語を変更できます。選択はインターフェースと .bat で共有されます
  （language.txt）。
  黒いコンソール画面で日本語・中国語を正しく表示するには Windows Terminal
  （Windows 11 の既定）を使ってください。

設置場所
  空白を含まないパスに、SSD 上で、80 GB 以上の空きがある場所に展開します。
  例：D:\AI\H3-LoRA\

使う順番
  1_INSTALLER.bat          初回のみ（10〜30 分）。MinGit、uv、Python 3.12、
                           torch、FFmpeg... すべてこのフォルダ内に入ります。
                           システムには何もインストールせず、Node.js も npm も
                           インストール・使用しません。
  2_LANCER_UI.bat          Python UI（Gradio）を開く：http://127.0.0.1:7860
  3_METTRE_A_JOUR.bat      git pull + 依存パッケージの再同期
  4_TELECHARGER_MODELE.bat 任意：重みを事前ダウンロード（UI の「モデル」タブ
                           でも可）
  2_LANCER_UI_ADMIN.bat    任意：管理者権限で同じ UI を起動し、Windows の確認
                           なしで GPU の電力上限を変更できます。
  DIAGNOSTIC.bat           問題があるとき：GPU、torch、int8 テスト、gradio
  （.bat の名前はフランス語です：INSTALLER = インストール、LANCER = 起動、
  METTRE_A_JOUR = 更新、TELECHARGER_MODELE = モデルのダウンロード。）

ダウンロードの進捗と再開
  - MinGit（SHA-256 を検証）/ uv：curl の進捗バー。.part ファイルは止まった
    ところから再開します（curl が失敗したら自動で BITS に切り替え）。
  - git リポジトリ：進捗を表示。中断したクローンは再開します。
  - Python、torch、依存パッケージ：進捗は uv が表示。ダウンロード済みの
    ものは cache\uv に残ります。
  - モデルの重み（約 30 GB）：ファイルごとに進捗バー（サイズ、速度、残り
    時間）、自動で 5 回まで再試行。.incomplete ファイルは再開します。
  - いずれの場合も：中断、ウィンドウを閉じた、再起動したときは同じ
    スクリプトを再実行してください。完了した手順は飛ばして続きを再開します。

どこに何があるか
  ai-toolkit\   ostris のリポジトリ（コード、.venv、.uv、.mingit、.ffmpeg）
  models\       MiniMax-H3-Image の重み（MODELS_PATH）
  datasets\     画像セット
  output\       学習済み LoRA、プレビュー、ジョブごとの journal_ui.txt
  configs\      UI が生成した YAML
  cache\        Hugging Face、triton、uv のキャッシュ
  manuals\      このマニュアル（7 言語）
  インストール先を移すには：フォルダごと移動し、ai-toolkit\.venv を削除して
  1_INSTALLER.bat を再実行します（venv には絶対パスが入っています。モデルと
  uv のキャッシュにより全部を再ダウンロードせずに済みます）。

UI（タブ）
  1. データセット   フォルダ、画像の追加、キャプションのチェック、
                    .txt のない画像の自動キャプション（Qwen3-VL）、
                    透かし・文字の切り取り。
  2. 学習           ヘルプと推奨値つきの設定、学習プロセス、
                    クイックテスト（20 ステップ）：速度とメモリを測り、設定と
                    所要時間を提案。ジョブごとの設定保存、キュー、
                    指定ステップ・時刻での自動一時停止。
  3. 結果           プレビュー、損失曲線、チェックポイント、ComfyUI への
                    コピー。5 秒ごとに自動更新。
  4. LoRAをテスト   同じプロンプト・同じシードで複数のチェックポイントを
                    生成し、最良のものを選ぶ（実験的）。
  モデル            事前ダウンロード + ファイルの状態。
  ツール            通知（音、ntfy.sh 経由のスマホ通知）、スリープ防止、
                    GPU の温度と電力、ComfyUI フォルダ、ai-toolkit の
                    バージョン固定 / 解除。
  上部：実行中のジョブ、フェーズ、進捗、VRAM / RAM / GPU 温度のモニター、
  一時停止・今すぐプレビュー・停止ボタン。
  各タブに専用の進捗表示とログがあります：キャプションは「データセット」、
  学習とクイックテストは「学習」、テストは「LoRAをテスト」、ダウンロードは
  「モデル」。進捗表示は段階を示し、所要時間を計れない間はアニメーション、
  その後は残り時間つきのバーを表示します。

学習プロセス（「学習」タブ）
  プロセスを選ぶと各欄が埋まります。あとからすべて変更できます。
  - ai-toolkit 標準：あなたの設定をそのまま使います。
  - 高速512：解像度 512、ランク 32、オプティマイザ automagic4（学習率を
    自動調整、開始値と上限 2.5e-4）、EMA 0.98、データセット 30 エポック。
    Fizgig が多くの試行の末に H3-Image 向けに選んだ設定を、ai-toolkit の
    部品で実現したものです。
  - Fizgig レシピ完全版（実験的）：同じ設定に加えて
      . Fizgig の学習用アダプタ（最初のジョブでダウンロードし、ai-toolkit
        形式に変換）
      . 類似度の最適化：最もシャープなノイズレベルをより頻繁に選びます
        （エポック 1、3、5 で 17、33、50 %、エポック 2、4、6 以降は 75 %）
      . プレビューを Euler ではなく LCM で生成
  後の 3 点は ai-toolkit のファイルを変更せず、メモリ上で調整します。
  コードが変わっていた場合は調整を行わず、ログに記録します（[H3-UI] の
  行）。Fizgig アダプタを使う最初のジョブでは、ログに
  「Adaptateur Fizgig converti : 200 modules」と出ることを確認してください。
  プロセスやアダプタを変えるときはジョブ名も変えてください。
  RAM ガード：RAM が足りないと、開始時とジョブ中に警告が表示されます
  （Windows ではカードのメモリが RAM に依存します）。

キャプション：最も大事なルール
  変わるものを書き、変わらないものは書かない。書いたものはキャプションの
  単語に結びつき、書かなかったものはトリガーワードに結びつきます。
  - キャラクター：髪、ひげ、体格、傷跡はキャプションに書かない。構図、角度、
    ポーズ、服装、背景、照明だけを書きます。
  - スタイル：逆に、内容はすべて書き、スタイルは書かない。
  - トリガーワードは数字入りの造語（m41ne）。実在の単語は使わない。
  - 1 枚 = 1 つの被写体、1 つの視点：複数視点のシートは分割します。
  「データセット」タブで、自動キャプションの前に「LoRA の種類」を選ぶと
  指示が切り替わります。その後「フォルダを分析」で、恒久的な特徴や複数の
  視点を書いたキャプションが一覧表示されます。
  キャプションはインターフェースの言語に関係なく英語のままです。

キャプションの修正（「データセット」タブ）
  「修正を提案」は、キャラクター LoRA のキャプションから恒久的な特徴（髪、ひげ、
  体格、傷跡、タトゥー、目の色など）と、入力した恒久的な要素を削除します。例：
  「m41ne, a muscular man with short spiky blond hair and a white beard,
  wearing a black vest」は「m41ne, a man, wearing a black vest」になります。
  表情や服装は残ります（「eyes closed」「skin-tight suit」）。各提案は表で編集
  でき、残したいものはチェックを外してから適用します。元のキャプションは
  <dataset>_legendes_originales に保存され、ワンクリックで復元できます。

データセットの監査（「データセット」タブ）
  「データセットを監査」は見落としがちな 3 つの問題を見つけます：
  - 画像の 30 % 以上に共通しキャプションに書かれていない単色の背景（白・黒・
    灰色など）：トリガーワードに結びつき、LoRA がどこにでも描くようになり
    ます。「背景をキャプションに追加」で該当キャプションを補完します（例：
    「white background」）。
  - ほぼ重複：切り抜きや再圧縮しただけの同じ画像で、二重に数えられます。
    各ペアで 1 枚だけ残してください。
  - 同じ構図の画像のグループ（データセットの他の画像より明らかに似ている
    もの）：変化をつけるか枚数を減らしてください。
  背景：画像の縁を解析。重複：CPU 上の DINOv2 モデル（約 90 MB、初回使用時
  にダウンロード）。

透かしと文字を切り取る（「データセット」タブ）
  文字検出器が透かし、署名、URL、キャプションを見つけ、各画像について
  文字を含まない最大の構図を提案します。画像は切り抜くだけで、塗りつぶしは
  しません。
  - 「画像を分析」：文字を赤、提案する切り抜きを緑、除外部分を暗くした
    サムネイルを表示。
  - 文字がシーンの一部である画像のチェックを外し、「切り抜く」。
  - 元画像はデータセットの隣の <dataset>_originaux にコピーされます
    （ai-toolkit はサブフォルダも読むため）。「すべての元画像を復元」で
    元に戻せます。
  - 文字が中央すぎる画像は「切り抜き不可」と判定されます。
  - 検出されないもの：文字のないロゴ、画像全体に繰り返された透かし。
  検出器（PP-OCRv3、2.4 MB）は初回使用時に models\outils にダウンロード
  されます。ネットワークがない場合は、精度の低い予備の検出器を使います。

推奨の進め方
  1. データセット + キャプション（自動生成してから見直す）。
  2. クイックテストを実行し、その推奨を適用。
  3. 学習（夜間に：ジョブ中は PC がスリープしません）。
  4. 「LoRAをテスト」で 2〜4 個のチェックポイントを比較し、最良のものを
     ComfyUI にコピー。
  5. すべて動いたら ai-toolkit のバージョンを固定。

3090 プリセット
  int8 + オフロード（既定） int8 の transformer、層の 35 % を RAM に置きます。
                           このモデル向けの ai-toolkit 既定値で、int8 演算は
                           3090 でネイティブ対応です。
                           3090 での実測：1024 + 1536 で 1 ステップ約 4〜7 秒。
  w4a8（実験的）           4 ビットの transformer、軽量でオフロード不要。
                           その triton カーネルは RTX 40 より前ではコンパイル
                           できない FP8 型を使うため、「w4a8 修正」（既定で
                           オン）で純粋な torch による展開を強制します。
                           3090 での実測：1 ステップ約 15 秒で、int8 より
                           明らかに遅いです。
  同じ設定は presets\ に YAML としてもあります（コマンドライン用）。

学習の一時停止・停止・再開
  - 「一時停止（状態を保存）」：現在のステップの終わりに、ai-toolkit が
    チェックポイント（LoRA + オプティマイザ + ステップ番号）を書き込み、
    きれいに停止します。再開時にやり直すのは多くても 1〜2 ステップです。
    一時停止中は VRAM が解放されます。
  - 再開：同じジョブ名で「開始 / 再開」ボタン。モデルを再読み込みし
    （数分）、latent / テキストのキャッシュは再利用します。UI を閉じた後や
    PC を再起動した後でも使えます。
  - 「保存せずに停止」：きれいに停止し、最後の自動チェックポイント
    （N ステップごと）から再開します。
  - 「今すぐプレビュー」：現在のステップの終わりにプレビューを生成。
  - 「結果」タブ：選択したジョブのプレビューとチェックポイントは自動で
    更新されます（5 秒）。開始したジョブが自動で選択されます。
  - 黒いウィンドウを閉じると即座に止まります：書き込み中のチェックポイントが
    壊れることがあります。再開時、UI は壊れたファイルを .corrompu に改名し、
    その前の有効なチェックポイントから再開します。
  技術メモ：UI は ai-toolkit 公式 UI と同じネイティブの仕組み（SQLite
  テーブル h3_ui.db：save_now / sample_now / stop）で制御しています。

GPU の温度と電力（「ツール」タブ）
  - 警告（既定 78 °C）：通知し、温度を赤で表示。
  - 自動一時停止（既定 88 °C、60 秒間）：保存して一時停止。安全網であり、
    制御ではありません。
  - 電力上限（ワット、0 = 変更しない）：多くの場合わずかな速度低下で発熱を
    抑えます（3090 では 240 W で約 60 °C、測定できる速度低下なし）。
    「保存」すると、ジョブ実行中なら中断せずにすぐ適用、そうでなければ
    次回開始時に適用します。「入力した値を今すぐ適用」と「元の上限に戻す」
    はいつでも使えます。管理者権限がない場合、変更のたびに Windows が確認を
    求め、キューのジョブは上限を変更せず、上限はジョブ後も残ります。
  - サーモスタット（チェックボックス）：ジョブ中 45 秒ごとに平均温度を目標
    （推奨 72 °C）と比較します。熱すぎれば上限を 10〜30 W 下げ、3 °C 以上
    下回れば 10 W 上げます。下限は調整可能（150 W）、上限は入力した電力上限
    （0 なら元の値）。2_LANCER_UI_ADMIN.bat が必要です。状態と最近の調整は
    「ツール」タブと上部バナーに表示されます。「下限に到達」は冷却が足りない
    という意味です。
  - ファンは UI では制御しません：MSI Afterburner か FanControl で曲線を
    設定してください。
  - モニターにはファンの回転数と消費電力も表示されます。

電気代（「ツール」タブ）
  1 kWh あたりの料金（電気料金の従量単価、基本料金を除く）と通貨（EUR、USD、
  GBP、BRL、JPY、CNY）を入力して保存します。ジョブ中は、経過時間・残り時間・
  速度の横に、GPU が消費した kWh、その料金、終了時の予想料金（直近 5 分間の
  平均電力から算出）が表示されます。合計はジョブ終了後も表示されたままです。
  数えるのはグラフィックカードだけ（nvidia-smi）で、PC の他の部分は含みません。
  料金が 0 の場合は kWh だけを表示します。

適切な電力上限を見つける（「結果」タブ）
  損失曲線の隣の「電力・速度・温度」タブは、学習中の GPU の電力、上限、温度、
  1 ステップあたりの時間を記録します（5 ステップごと、プレビューと保存は除外）。
  表は測定値を 10 W 刻みでまとめ、推奨しきい値（最高速度から 3 % 以内に収まる
  最も低い電力）を示します。「Wh/ステップ」の列は同じ作業に必要なエネルギー
  です。比較するには、学習中に上限を変える（「ツール」タブ）か、サーモスタット
  に任せてください。

自動電力スイープ（「ツール」タブ）
  「学習開始時の電力スイープ」ボックス（既定でオフ、2_LANCER_UI_ADMIN.bat が必要）。
  ジョブごとに 1 回、立ち上がりの 10 ステップの後、保存済みの上限（または元の
  値）から下限（3090 なら推奨 200 W）まで、30 W 刻み（変更可）・各 30 ステップ
  で上限を下げていきます：約 6〜8 分。その間も学習は通常どおり続きます。最後に、
  最高速度から 3 % 以内の最も低い段階を適用して電力上限として保存し、結果を通知
  します。サーモスタットはスイープの終了を待ち、その値を上限として使います。

チェックポイントを選ぶ：類似度（「結果」タブ）
  「類似度」タブは、学習中に CPU で各プレビューをデータセットの画像（DINOv2
  モデル）と、トリガーワードを除いたプロンプト（CLIP モデル）と比較します。
  類似度だけでは過学習が高く評価されるため、推奨チェックポイントは、最初
  （ステップ 0、LoRA なし）と同じようにプロンプトに従うものの中で最も似ている
  ものです。目安の値なので「LoRAをテスト」で確認してください。モデルは初回
  使用時にダウンロード（約 700 MB）。「ツール」で無効にできます。

にじみ出し：対照プロンプト
  過学習した LoRA は、トリガーワードがなくてもキャラクターを登場させます（バー
  の客が全員その顔になる）。これを測るには、プレビューに単語なしの対照プロン
  プトが必要です。「対照プロンプトを追加」（既定でオン、「学習」タブ）は、必要
  なら最初のプロンプトの単語を「a person」に置き換えて作成します。プロンプト
  の下に表示され、「LoRAをテスト」でも追加されます。「類似度」タブは、学習した
  類似度のうち対照プロンプトににじみ出した割合を計算します：30 % からオレン
  ジ、50 % から赤で、それらのチェックポイントは推奨から除外されます。学習中に
  強いにじみ出しがあると通知し、「ツール」で該当ボックスをオンにしていれば一時
  停止します。

にじみ出し：2 つの保護機能
  「プロセスオプション」の「にじみ出し対策」に、組み合わせ可能な
  ai-toolkit の保護機能が 2 つあります：
  - 保持（DOP）：トリガーワードを保持するクラス（a person、a man など）
    に置き換えたときにベースモデルが描くものを LoRA が変えると、各ステップで
    ペナルティが課されます。準備は不要ですが、1 ステップが約 1.6〜2 倍遅く
    なりメモリも増えます：クイックテストで確認してください。
  - 正則化画像：「正則化画像を生成」ボタンで、トリガーワードをクラスに
    置き換えたキャプションからベースモデル（LoRA なし）が画像を生成します。
    キャプションと共に <dataset>_regularisation に保存され、チェックを
    入れると学習に混ぜられます。1 ステップの速度は同じですが、ステップの
    一部を使います：データセットと同じ枚数ならステップを 2 倍に。
  「結果」>「類似度」の「にじみ出し」列を保護あり・なしで比べて選んで
  ください。

LoRA で生成する（「5. 生成」タブ）
  別途インストールした MiniMaxH3-Portable ジェネレーターを操作します
  （独自の install.bat と prepare.bat、変換済みモデル約 39 GB：学習側の
  ファイルは形式が異なり使えません）。このフォルダの隣にあれば自動検出、
  なければフォルダを指定します。ライセンスに同意し（注意を表示：EU、
  英国、韓国、米国では権利なし）、「ジェネレーターを起動」：1〜3 分後に
  タブ内（またはブラウザのタブ）に表示されます。言語はインターフェースに
  合わせます。「ジェネレーターに送る」（ここまたは「結果」）でチェック
  ポイントをその loras フォルダにコピーします。既定値は「類似度」タブの
  推奨です。ジェネレーター側で LoRA リストを更新してください。
  VRAM を約 20 GB 使うため、学習側のジョブが始まると先に自動停止し、
  ジョブ中は起動しません。

AI-TOOLKIT のバージョン

既知の制限
  - LoRAをテスト：学習ステップ 0 の ai-toolkit ジョブを利用しています。
  - 自動キャプション：モデルは初回使用時にダウンロード（10〜20 GB）。
  - 2048x2048 のプレビュー：デコードが 24 GB を超えることがあります。
    1536 に下げてください。
  - モデルの出力は 4 MP+ が前提ですが、Fizgig は 512 px で学習して良い結果を
    得ています。1 ステップの時間は主に解像度で決まります。
  - MiniMax-H3-Image の重みのライセンス：商用利用の前に Hugging Face の
    ページで確認してください。ここでは未確認です。

モデルの特性（変更しないこと）
  - CFG なしの 6 ステップに蒸留済み：sample_steps 6、guidance_scale 1。
  - 学習用アダプタ（アシスタント LoRA）を有効にして学習します。プレビュー時は
    自動で無効になります。
  - 4〜20 MP の出力向け：1024 のプレビューはアーティファクトが多めですが、
    正常です。UI は既定で 2048 で生成します。
  - 参照画像フォルダを指定すると編集モードで学習します（プロンプト内の参照は
    <Picture 1>、<Picture 2>...）。

RTX 3090（Ampere）- 知っておくべきこと
  - int8（convrot8 / w4a8）：ネイティブの int8 matmul、問題なし。
  - NVFP4 テキストエンコーダ：Ampere にはハードウェア FP4 がないため、その場で
    展開します。動作はしますが遅め。埋め込みはキャッシュされるので、使うのは
    最初だけです。
  - 高速な FP8 triton カーネルは Ada 以降が必要：自動で torch に切り替えます。
  - 83 °C を超えるとカードはクロックを下げます：ケースの通気に注意するか、
    電力上限とサーモスタットを使ってください。

メモリ不足のとき（CUDA out of memory）
  この順で：
  1. 解像度：1024 のみ（または 512）
  2. プレビューを 1536 にするか「プレビューを無効化」
  3. 「RAM に置く transformer の割合」：0.35 -> 0.5 -> 0.7
     - RAM 64 GB なら十分に対応できます
  4. LoRA ランク 16 -> 8
  重いブラウザやゲームは閉じてください：Windows はすでに約 1 GB の VRAM を
  確保しています。Windows のページングファイルは「システム管理」のままに
  （約 30 GB の重みを読み込むときに RAM 使用量がピークになります）。
