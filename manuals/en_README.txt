Portable AI Toolkit - MiniMax-H3-Image LoRA - WITHOUT Node.js or npm
Target: Windows 10/11, RTX 3090 24 GB, 64 GB RAM
=============================================================================

LANGUAGE
  Every .bat file starts by asking for the language (English, French,
  German, Spanish, Portuguese, Japanese, Mandarin). With no answer within
  10 s, the last chosen language is kept. In the interface, the selector at
  the top right changes the language at any time; the choice is shared
  between the interface and the .bat files (language.txt).
  For Japanese and Mandarin in the black console window, Windows Terminal
  (the default on Windows 11) displays the characters correctly.

LOCATION
  Unzip to a path WITHOUT spaces, on an SSD, with at least 80 GB free.
  Example: D:\AI\H3-LoRA\

ORDER OF USE
  1_INSTALLER.bat          Once (10 to 30 min). MinGit, uv, Python 3.12,
                           torch, FFmpeg... everything inside this folder.
                           Nothing is installed on the system, and neither
                           Node.js nor npm is installed or used.
  2_LANCER_UI.bat          Opens the Python UI (Gradio): http://127.0.0.1:7860
  3_METTRE_A_JOUR.bat      git pull + dependency resync
  4_TELECHARGER_MODELE.bat Optional: pre-downloads the weights (also possible
                           in the "Models" tab of the UI)
  2_LANCER_UI_ADMIN.bat    Optional: same UI with administrator rights, to
                           change the GPU power limit without a Windows
                           confirmation prompt.
  DIAGNOSTIC.bat           If something goes wrong: GPU, torch, int8 test, gradio
  (The .bat file names are in French: INSTALLER = install, LANCER = start,
  METTRE_A_JOUR = update, TELECHARGER_MODELE = download model.)

DOWNLOAD PROGRESS AND RESUME
  - MinGit (SHA-256 checked) / uv: curl progress bar; a .part file is
    resumed where it stopped (automatic fallback to BITS if curl fails).
  - git repository: progress shown; an interrupted clone is resumed.
  - Python, torch, dependencies: progress shown by uv; whatever is already
    downloaded stays in cache\uv.
  - Model weights (~30 GB): one bar per file (size, speed, time left),
    5 automatic attempts; an .incomplete file is resumed.
  - In every case: after an interruption, window close or reboot, RUN the
    same script AGAIN. Finished steps are skipped, the rest resumes.

WHAT LIVES WHERE
  ai-toolkit\   the ostris repository (code, .venv, .uv, .mingit, .ffmpeg)
  models\       MiniMax-H3-Image weights (MODELS_PATH)
  datasets\     your image sets
  output\       trained LoRAs, previews, journal_ui.txt per job
  configs\      YAML files generated by the UI
  cache\        Hugging Face, triton, uv caches
  manuals\      this manual, in 7 languages
  To move the installation: move the whole folder, delete
  ai-toolkit\.venv, then run 1_INSTALLER.bat again (the venv holds absolute
  paths; the models and the uv cache avoid downloading everything again).

THE UI (tabs)
  1. Dataset        folder, adding images, caption check,
                    AUTO-CAPTIONING (Qwen3-VL) of images without .txt,
                    cropping out watermarks and text.
  2. Training       settings with help and recommended values; training
                    processes; QUICK TEST (20 steps): measures speed and
                    memory, suggests settings and a duration; settings saved
                    per job; queue; automatic pause at a step or a time.
  3. Results        previews, LOSS CURVE, checkpoints, copy to ComfyUI.
                    Automatic refresh every 5 s.
  4. Test a LoRA    same prompts and same seed on several checkpoints, to
                    pick the best one (experimental).
  Models            pre-download + file status.
  Tools             notifications (sound, phone via ntfy.sh), sleep
                    prevention, GPU temperature and power, ComfyUI folder,
                    pin / unpin the ai-toolkit version.
  At the top: current job, phase, progress, VRAM / RAM / GPU temperature
  monitor, and the Pause, Preview now and Stop buttons.
  Each tab has its own tracking and log: captioning in Dataset, training
  and Quick test in Training, tests in Test a LoRA, downloads in Models.
  Tracking shows the steps, an animation while the duration cannot be
  measured, then a bar with the time left.

TRAINING PROCESSES (Training tab)
  Choosing a process fills in the fields; everything stays editable.
  - ai-toolkit standard: your settings, unchanged.
  - Fast 512: resolution 512, rank 32, automagic4 optimizer (self-tuned
    rate, start and ceiling 2.5e-4), EMA 0.98, 30 epochs over the dataset.
    These are the settings Fizgig chose for H3-Image after many trials;
    here with ai-toolkit's components.
  - Full Fizgig recipe (experimental): the same, plus
      . Fizgig's training adapter, downloaded then converted to the
        ai-toolkit format at the first job;
      . likeness optimization: the sharpest noise level is sampled more
        often (17, 33, 50 % at epochs 1, 3, 5; 75 % at epochs 2, 4, 6 and
        after);
      . LCM previews instead of Euler.
  These last three points adjust ai-toolkit in memory, without changing
  its files. If its code has changed, the adjustment backs off and says so
  in the log (lines [H3-UI]). At the first job with the Fizgig adapter,
  check the log for "Adaptateur Fizgig converti : 200 modules".
  Change the job name when you change process or adapter.
  RAM guard: a warning is shown at start and during the job if RAM runs
  short (on Windows, the card's memory depends on it).

CAPTIONS: THE RULE THAT MATTERS MOST
  Describe what varies, leave out what is permanent. What is described
  binds to the words of the caption; what is left out binds to the trigger
  word.
  - Character: no hair, beard, build or scars in the captions. Framing,
    angle, pose, outfit, background, lighting only.
  - Style: the opposite, all the content but not the style.
  - Trigger word invented with digits (m41ne), never a real word.
  - One image = one subject, one view: split multi-view sheets.
  In the Dataset tab: choose the "LoRA type" before auto-captioning (the
  instruction adapts), then "Analyze folder" lists the captions that
  describe permanent traits or several views.
  Captions stay in English whatever the interface language.

FIXING CAPTIONS (Dataset tab)
  "Suggest fixes" removes the permanent traits (hair, beard, build, scars,
  tattoos, eye color...) and the permanent elements you entered from the
  captions of a character LoRA. Example: "m41ne, a muscular man with short
  spiky blond hair and a white beard, wearing a black vest" becomes "m41ne,
  a man, wearing a black vest". Expressions and clothing stay ("eyes
  closed", "skin-tight suit"). Each proposal can be edited in the table;
  untick those to leave, then apply. Originals are saved in
  <dataset>_legendes_originales and can be restored in one click.

DATASET AUDIT (Dataset tab)
  "Audit the dataset" finds three flaws that go unnoticed:
  - the same plain background (white, black, gray...) on at least 30 % of
    the images and missing from the captions: it binds to the trigger word
    and the LoRA puts it everywhere. "Add the background to the captions"
    completes the captions concerned (for example "white background");
  - near-duplicates: the same image cropped or recompressed, which counts
    twice. Keep one per pair;
  - groups of images with the same framing, clearly more alike than the
    rest of the dataset: vary them or keep fewer.
  Backgrounds: analysis of the image edges. Duplicates: DINOv2 model on the
  processor (~90 MB, downloaded on first use).

CROPPING OUT WATERMARKS AND TEXT (Dataset tab)
  A text detector finds watermarks, signatures, website addresses and
  captions, then suggests for each image the largest framing that contains
  none. The image is only cropped, nothing is repainted.
  - "Analyze images": thumbnails with text in red, the suggested crop in
    green, the removed area darkened.
  - Untick images where the text is part of the scene, then "Crop".
  - Originals are copied to <dataset>_originaux, NEXT TO the dataset
    (ai-toolkit reads subfolders); "Restore all originals" puts them back.
  - An image whose text is too central is reported as not croppable.
  - Not detected: logos without text, watermarks tiled over the whole image.
  The detector (PP-OCRv3, 2.4 MB) is downloaded on first use into
  models\outils; without network, a less reliable fallback detector is used.

SUGGESTED WORKFLOW
  1. Dataset + captions (automatic, then reviewed).
  2. Quick test, and apply its recommendations.
  3. Training (overnight: the PC does not go to sleep during a job).
  4. Test a LoRA on 2 to 4 checkpoints, copy the best one to ComfyUI.
  5. Pin the ai-toolkit version once everything works.

3090 PRESETS
  int8 + offload (default) int8 transformer, 35 % of the layers in RAM.
                           This is ai-toolkit's default for this model and
                           int8 compute is native on the 3090.
                           Measured on a 3090: about 4 to 7 s per step at
                           1024 + 1536.
  w4a8 (EXPERIMENTAL)      4-bit transformer, lighter and without offload.
                           Its triton kernel uses an FP8 type that cannot be
                           compiled before RTX 40; the "w4a8 fix" box
                           (ticked by default) forces unpacking in pure
                           torch. Measured on a 3090: about 15 s per step,
                           i.e. clearly slower than int8.
  The same settings exist as YAML in presets\ (command line).

PAUSING, STOPPING AND RESUMING A TRAINING
  - "Pause (save state)": at the end of the current step, ai-toolkit
    writes a checkpoint (LoRA + optimizer + step number), then stops
    cleanly. At most one or two steps are redone on resume. VRAM is freed
    during the pause.
  - Resume: same job name, "Start / Resume" button. The model is reloaded
    (a few minutes), the latent/text caches are reused. Also works after
    closing the UI or restarting the PC.
  - "Stop without saving": clean stop, resume from the last automatic
    checkpoint (every N steps).
  - "Preview now": generates previews at the end of the current step.
  - Results tab: previews and checkpoints of the selected job update by
    themselves (5 s); the started job is selected automatically.
  - Closing the black window cuts off abruptly: a checkpoint being written
    may be truncated. On resume, the UI renames truncated files to
    .corrompu and restarts from the previous valid checkpoint.
  Technical note: the UI drives ai-toolkit through its native mechanism
  (SQLite table h3_ui.db: save_now / sample_now / stop), the one its
  official UI uses.

GPU TEMPERATURE AND POWER (Tools tab)
  - Alert (78 °C by default): notification, temperature shown in red.
  - Automatic pause (88 °C by default, for 60 s): pause with save. A safety
    net, not regulation.
  - Power limit in watts (0 = unchanged): reduces heat for a usually small
    speed loss (on a 3090, 240 W gave about 60 °C with no measurable speed
    loss). "Save" applies it right away if a job is running (without
    interrupting it), otherwise at the next start. "Apply the entered value
    now" and "Restore original limit" work at any time. Without
    administrator rights, Windows asks for confirmation at each change,
    queued jobs do not change the limit, and it stays in place after the job.
  - Thermostat (checkbox): every 45 s during a job, compares the average
    temperature with the target (72 °C recommended). Too hot: lowers the
    limit by 10 to 30 W. More than 3 °C below: raises it by 10 W.
    Adjustable floor (150 W), ceiling = the entered power limit, or the
    original one if 0. Requires 2_LANCER_UI_ADMIN.bat. Status and latest
    adjustments are shown in the Tools tab and the top banner.
    "Floor reached" means cooling is not enough.
  - Fans are NOT controlled by the UI: set a curve in MSI Afterburner or
    FanControl.
  - The monitor also shows fan speed and power draw.

ELECTRICITY COST (Tools tab)
  Enter the price per kWh (from your bill, excluding the standing charge)
  and the currency (EUR, USD, GBP, BRL, JPY, CNY), then Save. During a job,
  next to the elapsed time, time left and speed, the UI shows the kWh used
  by the GPU, their cost and the projected cost at the end (based on the
  average power of the last 5 minutes). The total stays visible when the
  job ends. Only the graphics card is counted (nvidia-smi): the rest of the
  PC comes on top. Price at 0: only kWh are shown.

FINDING THE RIGHT POWER LIMIT (Results tab)
  The "Power, speed and temperature" tab, next to the loss curve, records
  during training the GPU power, its limit, the temperature and the time
  per step (in blocks of 5 steps, previews and saves excluded). A table
  groups the measurements in 10 W levels and points out the recommended
  threshold: the lowest power that stays within 3 % of the top speed. The
  "Wh per step" column gives the energy for the same work. To compare, vary
  the limit during a training (Tools tab) or let the thermostat act.

AUTOMATIC POWER SWEEP (Tools tab)
  "Power sweep at the start of training" box (unticked by default, needs
  2_LANCER_UI_ADMIN.bat). Once per job, after 10 warm-up steps, the limit
  goes down in levels of 30 W (adjustable), 30 steps each, from the saved
  limit (or the original one) to the floor (200 W recommended on a 3090):
  about 6 to 8 minutes. Training carries on normally meanwhile. At the end,
  the lowest level within 3 % of the top speed is applied and saved as the
  power limit, and a notification gives the result. The thermostat waits
  for the sweep to finish, then uses it as its ceiling.

CHOOSING THE CHECKPOINT: LIKENESS (Results tab)
  The "Likeness" tab compares each preview with the dataset images (DINOv2
  model) and with its prompt without the trigger word (CLIP model), on the
  processor during training. Likeness alone would reward overfitting: the
  recommended checkpoint is the most alike among those that still follow
  the prompt as at the start (step 0, without LoRA). Indicative measurements,
  to confirm with Test a LoRA. Models downloaded on first use (about
  700 MB); can be turned off in Tools.

BLEEDING: THE CONTROL PROMPT
  An overtrained LoRA makes the character appear even without its trigger
  word (every customer in the bar gets its face). To measure it, the
  previews need a control prompt without the word. The "Add a control
  prompt" box (ticked by default, Training tab) creates it when needed: the
  first prompt with "a person" in place of the word; it is shown under the
  prompts, and Test a LoRA adds it too. The Likeness tab then computes the
  share of the learned likeness that bleeds into this control: orange from
  30 %, red from 50 %; those checkpoints are left out of the
  recommendation. During training, strong bleeding sends a notification,
  and pauses if the matching box is ticked in Tools.

BLEEDING: THE TWO PROTECTIONS
  In Process options, section "Against bleeding", two ai-toolkit
  protections, which can be combined:
  - Preservation (DOP): at each step, the LoRA is penalized if it changes
    what the base model draws when the trigger word is replaced by the
    preserved class (a person, a man...). Nothing to prepare, but each step
    is about 1.6 to 2 times slower and needs more memory: check with the
    Quick test.
  - Regularization images: the "Generate regularization images" button
    has the base model (without LoRA) produce images from your captions,
    trigger word replaced by the class. They are stored in
    <dataset>_regularisation with their captions, then mixed into training
    if the box is ticked. Same speed per step, but they take a share of
    the steps: double the steps with as many images as the dataset.
  Compare the Bleeding column in Results > Likeness with and without
  protection to choose.
  With an automagic optimizer (Fast 512 and Fizgig processes),
  regularization images make its rate collapse (found by Fizgig): the
  tool then switches to adamw8bit at 2e-4 and says so at launch. With DOP
  preservation, it only warns. In every case the learning rate is shown
  next to the speed, and an alert is sent if it stays below 1e-6: pause
  and restart with adamw8bit.

AI-TOOLKIT VERSION
  By default: latest version of the main branch. This package was audited
  on commit 4a7f285 (10 Nov 2026). "Pin current version" button in the
  Tools tab: 3_METTRE_A_JOUR.bat then no longer changes the code.

KNOWN LIMITATIONS
  - Test a LoRA: relies on an ai-toolkit job with 0 training steps.
  - Auto-captioning: model downloaded on first use (10 to 20 GB).
  - Previews at 2048x2048: decoding may exceed 24 GB; lower to 1536.
  - The model targets 4 MP+ output; Fizgig nevertheless trains at 512 px
    with good results, and step time depends mostly on resolution.
  - MiniMax-H3-Image weights license: read it on the Hugging Face page
    before any commercial use; not checked here.

MODEL SPECIFICS (do not change)
  - Distilled to 6 steps without CFG: sample_steps 6, guidance_scale 1.
  - Training runs with the training adapter (assistant LoRA) active; it is
    switched off automatically for previews.
  - Designed for 4 to 20 MP output: previews at 1024 show more artifacts,
    this is normal. By default the UI samples at 2048.
  - With a reference images folder, it learns in edit mode (references
    called <Picture 1>, <Picture 2>... in the prompt).

RTX 3090 (Ampere) - WHAT YOU NEED TO KNOW
  - int8 (convrot8 / w4a8): native int8 matmul, OK.
  - NVFP4 text encoder: no hardware FP4 on Ampere, it is unpacked on the
    fly. It works, just more slowly; and since embeddings are cached, it is
    only used at the start.
  - Fast FP8 triton kernels need Ada+: automatic torch fallback.
  - Above 83 °C the card lowers its clocks: watch the case airflow, or use
    the power limit and the thermostat.

IF IT RUNS OUT OF MEMORY (CUDA out of memory)
  In this order:
  1. resolutions: 1024 only (or 512)
  2. previews at 1536, or "Disable previews"
  3. "Transformer share in RAM" slider: 0.35 -> 0.5 -> 0.7
     - 64 GB of RAM handles it easily
  4. LoRA rank 16 -> 8
  Close heavy browsers and games: Windows already reserves ~1 GB of VRAM.
  Windows page file: leave it "system managed" (RAM peak while loading the
  ~30 GB of weights).
