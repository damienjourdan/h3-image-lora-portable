便携版 AI Toolkit - MiniMax-H3-Image LoRA - 无需 Node.js 和 npm
目标：Windows 10/11，RTX 3090 24 GB，64 GB 内存
=============================================================================

语言
  每个 .bat 文件启动时都会先询问语言（英语、法语、德语、西班牙语、葡萄牙语、
  日语、中文）。10 秒内不作答则沿用上次选择的语言。在界面中，右上角的选择器
  可随时切换语言；该选择在界面和 .bat 之间共享（language.txt）。
  要在黑色控制台窗口中正确显示中文和日文，请使用 Windows Terminal
  （Windows 11 默认）。

安装位置
  解压到不含空格的路径，放在 SSD 上，至少留出 80 GB 空间。
  示例：D:\AI\H3-LoRA\

使用顺序
  1_INSTALLER.bat          只需一次（10 到 30 分钟）。MinGit、uv、Python 3.12、
                           torch、FFmpeg……全部装在本文件夹内。
                           不会在系统中安装任何东西，也不安装、不使用
                           Node.js 和 npm。
  2_LANCER_UI.bat          打开 Python 界面（Gradio）：http://127.0.0.1:7860
  3_METTRE_A_JOUR.bat      git pull + 重新同步依赖
  4_TELECHARGER_MODELE.bat 可选：预先下载权重（也可在界面的“模型”标签页完成）
  2_LANCER_UI_ADMIN.bat    可选：以管理员权限打开同一界面，修改 GPU 功率上限时
                           无需 Windows 确认窗口。
  DIAGNOSTIC.bat           出问题时使用：GPU、torch、int8 测试、gradio
  （.bat 文件名为法语：INSTALLER = 安装，LANCER = 启动，
  METTRE_A_JOUR = 更新，TELECHARGER_MODELE = 下载模型。）

下载进度与续传
  - MinGit（校验 SHA-256）/ uv：curl 进度条；.part 文件会从中断处续传
    （curl 失败时自动改用 BITS）。
  - git 仓库：显示进度；中断的克隆会继续。
  - Python、torch、依赖：进度由 uv 显示；已下载的内容保留在 cache\uv 中。
  - 模型权重（约 30 GB）：每个文件一个进度条（大小、速度、剩余时间），
    自动重试 5 次；.incomplete 文件会续传。
  - 任何情况下：遇到中断、关闭窗口或重启后，重新运行同一个脚本即可。
    已完成的步骤会被跳过，其余部分继续。

文件位置
  ai-toolkit\   ostris 仓库（代码、.venv、.uv、.mingit、.ffmpeg）
  models\       MiniMax-H3-Image 权重（MODELS_PATH）
  datasets\     你的图片集
  output\       训练好的 LoRA、预览、每个任务的 journal_ui.txt
  configs\      界面生成的 YAML
  cache\        Hugging Face、triton、uv 缓存
  manuals\      本手册（7 种语言）
  迁移安装：移动整个文件夹，删除 ai-toolkit\.venv，然后重新运行
  1_INSTALLER.bat（venv 包含绝对路径；模型和 uv 缓存可避免全部重新下载）。

界面（标签页）
  1. 数据集         文件夹、添加图片、检查描述、为没有 .txt 的图片
                    自动描述（Qwen3-VL）、裁掉水印和文字。
  2. 训练           带帮助和推荐值的设置；训练流程；快速测试（20 步）：
                    测量速度和显存，给出设置和时长建议；按任务保存设置；
                    队列；在指定步数或时间自动暂停。
  3. 结果           预览、损失曲线、检查点、复制到 ComfyUI。
                    每 5 秒自动刷新。
  4. 测试 LoRA      用相同的提示词和种子测试多个检查点，以选出最好的
                    （实验性）。
  模型              预先下载 + 文件状态。
  工具              通知（声音、通过 ntfy.sh 推送到手机）、防止休眠、
                    GPU 温度与功率、ComfyUI 文件夹、锁定 / 解锁 ai-toolkit 版本。
  顶部：当前任务、阶段、进度、显存 / 内存 / GPU 温度监视，以及
  暂停、立即预览、停止按钮。
  每个标签页都有自己的进度和日志：描述在“数据集”，训练和快速测试在“训练”，
  测试在“测试 LoRA”，下载在“模型”。进度会显示各阶段；无法估算时长时显示
  动画，之后显示带剩余时间的进度条。

训练流程（“训练”标签页）
  选择流程会自动填写各字段；之后一切仍可修改。
  - ai-toolkit 标准：你的设置，保持不变。
  - 快速 512：分辨率 512，秩 32，优化器 automagic4（自调学习率，起点和上限
    2.5e-4），EMA 0.98，数据集训练 30 轮。这是 Fizgig 经过多次尝试为
    H3-Image 选定的设置；这里用 ai-toolkit 的组件实现。
  - 完整 Fizgig 配方（实验性）：同上，外加
      . Fizgig 的训练适配器，首个任务时下载并转换为 ai-toolkit 格式；
      . 相似度优化：更频繁地抽取最清晰的噪声级别（第 1、3、5 轮为 17、33、
        50 %；第 2、4、6 轮及以后为 75 %）；
      . 预览使用 LCM 而不是 Euler。
  最后三点在内存中调整 ai-toolkit，不修改其文件。如果其代码已变更，调整会
  自动放弃并写入日志（[H3-UI] 行）。首次使用 Fizgig 适配器时，请在日志中
  确认“Adaptateur Fizgig converti : 200 modules”。
  更换流程或适配器时请更换任务名称。
  内存保护：内存不足时，启动和任务期间会显示警告（在 Windows 上显卡内存
  依赖于系统内存）。

描述：最重要的规则
  描述会变化的，不写永久不变的。写进描述的内容会绑定到描述中的词；没写的
  内容会绑定到触发词。
  - 角色：描述中不要写头发、胡子、体型或伤疤。只写构图、角度、姿势、服装、
    背景、光照。
  - 风格：相反，写全部内容，但不写风格。
  - 触发词用带数字的自造词（m41ne），绝不用真实单词。
  - 一张图 = 一个主体、一个视角：拆分多视角的设定图。
  在“数据集”标签页：自动描述前先选择“LoRA 类型”（指令会随之调整），然后
  “分析文件夹”会列出描述了永久特征或多个视角的描述。
  无论界面语言如何，描述都保持英文。

修正描述（“数据集”标签页）
  “生成修正建议”会从角色 LoRA 的描述中删除永久特征（头发、胡子、体型、伤疤、
  纹身、眼睛颜色等）以及你输入的永久元素。例如：“m41ne, a muscular man with
  short spiky blond hair and a white beard, wearing a black vest”会变成
  “m41ne, a man, wearing a black vest”。表情和服装会保留（“eyes closed”、
  “skin-tight suit”）。每条建议都可在表格中编辑；取消勾选要保留的，然后应用。
  原始描述保存在 <dataset>_legendes_originales，可一键恢复。

数据集审核（“数据集”标签页）
  “审核数据集”会找出三种容易被忽略的问题：
  - 至少 30 % 的图片共用、描述中却未提及的纯色背景（白、黑、灰等）：它会绑
    定到触发词，LoRA 会处处画上它。“把背景添加到描述”会补充相关描述（例如
    “white background”）；
  - 近似重复：只是裁剪或重新压缩过的同一张图片，会被计算两次。每组保留一张；
  - 构图相同、明显比数据集其他图片更相似的图片组：请增加变化或减少数量。
  背景：分析图片边缘。重复：在处理器上运行的 DINOv2 模型（约 90 MB，首次使
  用时下载）。

裁掉水印和文字（“数据集”标签页）
  文字检测器会找出水印、签名、网址和图注，并为每张图片建议不含文字的最大
  构图。图片只会被裁剪，不会重绘。
  - “分析图片”：缩略图中文字为红色，建议的裁剪为绿色，去除的区域变暗。
  - 取消勾选文字属于场景一部分的图片，然后“裁剪”。
  - 原图复制到数据集旁边的 <dataset>_originaux（ai-toolkit 会读取子文件夹）；
    “恢复全部原图”可还原。
  - 文字太靠中间的图片会被判定为不可裁剪。
  - 无法检测：没有文字的标志，以及铺满整张图的重复水印。
  检测器（PP-OCRv3，2.4 MB）在首次使用时下载到 models\outils；没有网络时
  使用可靠性较低的备用检测器。

建议流程
  1. 数据集 + 描述（自动生成后人工检查）。
  2. 运行快速测试，并采用其建议。
  3. 训练（夜间进行：任务期间电脑不会休眠）。
  4. 在“测试 LoRA”中比较 2 到 4 个检查点，把最好的复制到 ComfyUI。
  5. 一切正常后锁定 ai-toolkit 版本。

3090 预设
  int8 + 卸载（默认）      int8 transformer，35 % 的层放在内存中。
                           这是该模型的 ai-toolkit 默认设置，int8 计算在 3090
                           上原生支持。3090 实测：1024 + 1536 下每步约 4 到 7 秒。
  w4a8（实验性）           4 位 transformer，更轻，无需卸载。
                           其 triton 内核使用的 FP8 类型在 RTX 40 之前无法编译；
                           “w4a8 修正”复选框（默认勾选）会强制用纯 torch 解包。
                           3090 实测：每步约 15 秒，明显慢于 int8。
  presets\ 中有相同设置的 YAML（命令行使用）。

暂停、停止和继续训练
  - “暂停（保存状态）”：在当前步结束时，ai-toolkit 写入检查点（LoRA + 优化器
    + 步数），然后正常停止。继续时最多重做一两步。暂停期间会释放显存。
  - 继续：使用相同任务名，点击“开始 / 继续”。模型会重新加载（几分钟），
    latent / 文本缓存会被复用。关闭界面或重启电脑后同样可用。
  - “停止且不保存”：正常停止，从最后一个自动检查点（每 N 步）继续。
  - “立即预览”：在当前步结束时生成预览。
  - “结果”标签页：所选任务的预览和检查点会自动更新（5 秒）；启动的任务会被
    自动选中。
  - 直接关闭黑色窗口会立刻中断：正在写入的检查点可能被截断。继续时，界面会把
    截断的文件重命名为 .corrompu，并从之前有效的检查点继续。
  技术说明：界面通过 ai-toolkit 的原生机制（SQLite 表 h3_ui.db：save_now /
  sample_now / stop）进行控制，与其官方界面相同。

GPU 温度与功率（“工具”标签页）
  - 警告（默认 78 °C）：发送通知，温度标红。
  - 自动暂停（默认 88 °C，持续 60 秒）：保存并暂停。这是安全保障，不是调节。
  - 功率上限（瓦，0 = 不变）：通常以很小的速度损失降低发热（在 3090 上，
    240 W 时约 60 °C，且无可测的速度损失）。“保存”后，若有任务在运行则立即
    生效（不会中断任务），否则在下次启动时生效。“立即应用输入的值”和“恢复
    原始上限”随时可用。没有管理员权限时，每次更改 Windows 都会要求确认，
    队列中的任务不会修改上限，且上限在任务结束后仍保留。
  - 恒温（复选框）：任务期间每 45 秒把平均温度与目标（建议 72 °C）比较。
    过热：上限降低 10 到 30 W。低于目标 3 °C 以上：提高 10 W。下限可调
    （150 W），上限 = 输入的功率上限（为 0 时为原始值）。需要
    2_LANCER_UI_ADMIN.bat。状态和最近的调整显示在“工具”标签页和顶部横幅中。
    “已达下限”表示散热不足。
  - 界面不控制风扇：请在 MSI Afterburner 或 FanControl 中设置曲线。
  - 监视器还会显示风扇转速和功耗。

电费（“工具”标签页）
  输入每 kWh 电价（电费账单上的单价，不含固定费用）和货币（EUR、USD、GBP、
  BRL、JPY、CNY），然后保存。任务期间，已用时间、剩余时间和速度旁边会显示
  GPU 消耗的 kWh、对应电费，以及预计结束时的总电费（按最近 5 分钟的平均功率
  计算）。任务结束后总额仍会显示。只统计显卡（nvidia-smi）：电脑其他部分的
  耗电不计入。电价为 0 时只显示 kWh。

找到合适的功率上限（“结果”标签页）
  损失曲线旁的“功率、速度与温度”标签页会在训练期间记录 GPU 功率、上限、温度
  和每步耗时（每 5 步一次，不含预览和保存）。表格按 10 W 档位汇总测量结果，
  并标出推荐阈值：速度损失在 3 % 以内的最低功率。“每步 Wh”一列表示完成相同
  工作所需的能量。要进行比较，请在训练期间改变上限（“工具”标签页）或让恒温
  功能自动调整。

选择检查点：相似度（“结果”标签页）
  “相似度”标签页会在训练期间于处理器上把每张预览与数据集图片比较（DINOv2
  模型），并与去掉触发词的提示词比较（CLIP 模型）。只看相似度会偏向过拟合：
  推荐检查点是在仍像开始时（第 0 步，无 LoRA）一样遵循提示词的检查点中最
  相似的那个。数值仅供参考，请用“测试 LoRA”确认。模型在首次使用时下载
  （约 700 MB）；可在“工具”中关闭。

外溢：对照提示词
  训练过度的 LoRA 会让角色在没有触发词时也出现（酒吧里所有客人都长成他的样
  子）。要测量外溢，预览中需要一个不含触发词的对照提示词。“添加对照提示词”
  （默认勾选，“训练”标签页）会在需要时创建：把第一个提示词中的触发词换成
  “a person”；它显示在提示词下方，“测试 LoRA”也会添加它。“相似度”标签页随后
  计算学到的相似度中外溢到对照提示词的比例：30 % 起标橙，50 % 起标红；这些检
  查点不参与推荐。训练期间外溢严重时会发送通知，若在“工具”中勾选了相应选项则
  自动暂停。

AI-TOOLKIT 版本
  默认：main 分支的最新版本。本软件包已在提交 4a7f285（2026 年 11 月 10 日）
  上审核。在“工具”标签页点击“锁定当前版本”后，3_METTRE_A_JOUR.bat 将不再
  修改代码。

已知限制
  - 测试 LoRA：基于一个 0 训练步的 ai-toolkit 任务。
  - 自动描述：模型在首次使用时下载（10 到 20 GB）。
  - 2048x2048 预览：解码可能超过 24 GB；请降到 1536。
  - 模型面向 4 MP+ 输出；不过 Fizgig 用 512 px 训练也取得了好效果，每步时间
    主要取决于分辨率。
  - MiniMax-H3-Image 权重的许可证：商用前请在 Hugging Face 页面阅读；此处
    未核实。

模型特性（请勿修改）
  - 蒸馏为 6 步、无 CFG：sample_steps 6，guidance_scale 1。
  - 训练时启用训练适配器（辅助 LoRA）；生成预览时会自动关闭。
  - 面向 4 到 20 MP 输出：1024 的预览伪影较多，属正常现象。界面默认以 2048
    生成预览。
  - 指定参考图片文件夹时，以编辑模式学习（提示词中的参考图写作
    <Picture 1>、<Picture 2>……）。

RTX 3090（Ampere）须知
  - int8（convrot8 / w4a8）：原生 int8 矩阵乘法，没问题。
  - NVFP4 文本编码器：Ampere 没有硬件 FP4，会实时解包。可以运行，只是更慢；
    而且嵌入会被缓存，所以只在开始时使用。
  - 快速的 FP8 triton 内核需要 Ada 及以上：自动改用 torch。
  - 超过 83 °C 时显卡会降频：注意机箱通风，或使用功率上限和恒温功能。

显存不足时（CUDA out of memory）
  依次尝试：
  1. 分辨率：只用 1024（或 512）
  2. 预览改为 1536，或“关闭预览”
  3. “放在内存中的 transformer 比例”：0.35 -> 0.5 -> 0.7
     - 64 GB 内存完全够用
  4. LoRA 秩 16 -> 8
  关闭占用大的浏览器和游戏：Windows 已经占用约 1 GB 显存。
  Windows 页面文件：保持“系统管理”（加载约 30 GB 权重时内存占用会达到峰值）。
